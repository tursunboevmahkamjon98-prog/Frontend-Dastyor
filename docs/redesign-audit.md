# Dastyor redesign — Phase 0 audit

Date: 2026-10-21. Scope note: a prior conversation already agreed the
request is "finish/verify the in-progress redesign," not "restart it" —
see the decision log at the end of this file before reading this as a
green-field plan.

## 1. Verified technology stack

- **Frontend**: Next.js 16.3.0 (App Router, Turbopack), React 19.2.8,
  TypeScript 5, Tailwind CSS 4 (CSS-variable tokens generated by
  `frontend/scripts/design_tokens.py`, not hand-written). `katex` for math
  rendering, `three`/`@react-three/fiber` for a 3D classroom scene used in
  one of the educational games, `lucide-react` for icons.
- **Backend**: FastAPI (`backend/app/main.py`), SQLAlchemy 2.0 async +
  Alembic migrations, PostgreSQL (via `asyncpg`/`psycopg`), JWT auth
  (`python-jose`), `bcrypt` password hashing. Document generation via
  `python-docx`, `python-pptx`, `reportlab`; `rembg` for local image
  cutouts; `pypdf` for PDF text extraction ("book mode" source uploads).
- **Mobile**: Flutter app at the repo root (`lib/`, `android/`, `ios/`),
  sharing the backend API. Prebuilt APK shipped at
  `frontend/public/dastyor.apk` and linked from the landing page.
- **Deploy**: `docker-compose.yml` at repo root; production is reached
  only via `git pull && docker compose up -d --build` on the server — no
  nginx/`.env`/log access from this side (see memory
  `dastyor-server-access`). `start.sh`/`start.bat` exist for local dev.
- **This machine** has no usable local `python` or `docker` on PATH (Store
  alias stubs only) — backend changes here can only be verified by static
  reading, not executed or tested locally.

## 3. Existing features that must be preserved (confirmed present, not demo code)

- JWT auth with refresh tokens, Google Sign-In, **phone+OTP+password**
  registration/login with a real Tajik SMS gateway (not simulated), QR-code
  auth (`routers/qr_auth.py`).
- Role-based admin area (`app/admin/*`, `routers/admin.py`) — view/manage
  teachers and their generated materials.
- Billing/balance (`routers/billing.py`, `dashboard/billing`), plus a
  separate, **unrelated and currently uncommitted** Telegram bot for
  billing/top-up (`backend/app/telegram/`, `topic_guard.py`,
  `TELEGRAM_BOT.md`) — out of scope for this redesign, flagged so it isn't
  mistaken for part of it.
- Real material generation against a hosted LLM (`ai_service.py`), with an
  offline rule-based fallback already built and ready to wire in (see
  `C:\Users\user\dastyor`), not yet connected.
- Document export in real formats: DOCX, PPTX, PDF — not placeholders.
- Flutter mobile app with its own onboarding, dashboard, admin, billing,
  and in-app update-check flow.
- Full ru/tg/en localization, both server- and client-side, with
  TypeScript enforcing key parity across locales (a missing translation
  key is a compile error, not a runtime gap).

## 4. Redesign already in progress (uncommitted, ~137 files)

This is the load-bearing finding of this audit: most of what the brief
asks for under "landing page redesign" and "dashboard redesign" already
has real, wired-up code sitting uncommitted in the working tree. Verified
in this session:

- **Brand**: red (`#e11d2e`, off the official logo sheet) on warm
  off-white neutrals, WCAG-AA-checked token generator
  (`frontend/scripts/design_tokens.py` → `globals.css`), light + dark
  theme (`lib/theme.tsx`, `ThemeToggle.tsx`). This *was* briefly tried as
  indigo earlier the same day and deliberately reverted — the generator's
  own header documents why (logo/mascot consistency outweighed the
  error-color collision risk, which is managed via fill-only brand red +
  a separate, desaturated `--color-error`).
- **Logo + mascot**: `components/Logo.tsx`, `components/Mascot.tsx` (5
  moods: idle/writing/happy/celebrating/sad, SVG+CSS keyframes, no
  external animation runtime), new asset set under `assets/mascot/` and
  `frontend/public/mascot/`.
- **Landing page**: `components/LandingPage.tsx` (387 lines) assembled
  from `components/landing/{LandingNav,ProductPreview,SubjectStrip,
  sections.ts}` + `HeroDocuments.tsx`. `ProductPreview` is a disciplined
  illustration — every subject/grade/material-type label is imported from
  the same constants the real create screen uses (`lib/material-types.ts`),
  not retyped, so it can't drift into advertising a feature that doesn't
  exist. One hardcoded, non-localized example string (`"Фотосинтез"`)
  was found and fixed in this session (now `t("landing.preview.topic")`,
  translated in all three locales).
- **Dashboard shell**: `app/dashboard/layout.tsx` was rewritten (not
  restyled — rationale documented inline) to add a desktop top bar,
  move account controls off the sidebar brand row, and center the mobile
  tab bar's create action. Built on new `components/dashboard/{SidebarNav,
  GlobalSearch,TopicComposer,TypeGrid,RecentList}`.
- **Admin separation**: `app/admin/layout.tsx` already redirects non-admin
  users client-side (`user.role !== "admin"` → `/dashboard`). Server-side
  enforcement lives in `routers/admin.py` and wasn't re-audited in this
  pass (out of scope: no backend changes were made or reviewed line-by-line).

## 6. Known gaps / not fixed in this pass

- **`npm run lint`**: 19 errors, all `react-hooks/set-state-in-effect`
  (a stricter rule shipped with this `eslint-config-next` version),
  spread across `auth-context.tsx`, `i18n.tsx`, `use-online-status.ts`,
  `Reveal.tsx`, `SamplesGallery.tsx`, `PdfPreview.tsx`. These are
  **pre-existing patterns, not introduced by the redesign** — mounted
  flags and loading-state init, mostly idiomatic even if the new rule
  flags them. Left alone pending a decision on whether to fix as a
  separate pass; fixing 19 call sites across unrelated files isn't part
  of a visual-redesign verification.
- **No visual/pixel verification possible this session** — the Chrome
  browser extension was not connected, so hero rendering, mobile nav
  behavior, responsive breakpoints (360/390/768/1024/1440), and console
  errors could only be checked at the HTTP-status level (all 200), not
  visually. This should be re-run with the browser extension connected
  before calling the redesign done.
- **Backend cannot be exercised locally** on this machine (no python/docker
  on PATH) — `ai_service.py`, `routers/*`, OTP rate-limiting, and the
  telegram bot are unreviewed beyond what's described above. Verification
  has to happen via `git pull && docker compose up -d --build` on the
  server, or by the user running it locally where Python/Docker exist.
- **Admin server-side authorization** (as opposed to the client-side
  redirect already confirmed) was not re-verified this pass.
- Password + OTP registration is **intentionally kept as-is** — a prior
  decision in this conversation chose not to move to OTP-only auth, since
  the brief's "phone-first" framing undersold an existing, real security
  property (OTP-only is vulnerable to SIM swap; password is not).

## 7. Risks / dependencies

- The public deploy repo (`Frontend-Dastyor`) does **not** yet have any of
  this redesign — it will need to be re-expressed there (not copied
  file-for-file; the two frontends have already diverged on the design
  token system) before `rahnamo.tj` reflects any of it.
- A second, unrelated feature (Telegram billing bot) shares the same
  uncommitted working tree. Any future `git add`/commit pass needs to
  separate these deliberately, or the redesign commit will silently bundle
  an unrelated, less-tested feature.
- 193 total uncommitted changes (redesign + telegram bot + some binary
  asset/icon regenerations) is a lot of surface to commit at once. Worth
  committing in reviewed, separable chunks rather than one giant commit,
  once the user is ready to commit at all — not done in this pass since
  committing wasn't requested.
